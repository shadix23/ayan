# EdTech V2 — конкретизация реализации

Этот документ дополняет MASTER_PROMPT.md. Это требования к будущей работе Claude Code, а не отчёт о готовом приложении. Продолжать существующий проект; сначала сопоставить требования с уже реализованным кодом. Не заменять стек и не начинать проект заново.

## 1. Границы локального этапа

- Только локальные файлы, локальный backend, localhost и синтетические пользователи. Сервер разработки привязать к loopback, если существующий проект не требует иного для локального теста.
- Никакого деплоя, preview deployment, git push, запуска внешнего CI/CD, production-БД или платных API. Наличие ключа в окружении не является разрешением его использовать.
- ElevenLabs и VideoCraft — будущие адаптеры; в этом этапе используются локальные fixtures и mock providers. Не устанавливать новый платный сервис ради демонстрации.
- Сохранить работающие возможности первого ТЗ. Неизвестные требования первого ТЗ отметить в gap-отчёте, а не выдумывать их содержание.
- Тесты и проверку типов запускать по затронутым модулям; итоговую локальную сборку выполнить один раз после интеграции, если она предусмотрена проектом.

## 2. Состав рабочего MVP

Один законченный сценарий: вход синтетического ученика → продолжение урока → пять видимых этапов → короткий видеофрагмент → Fraction World в 3D/2D/простом режиме → помощь или перерыв → проверка ответа → завершение → отчёт назначенного учителя. Параллельно подготовить шесть двуязычных уроков и библиотеку. Не показывать неработающие кнопки как готовые функции.

Главная ученика содержит три крупных действия: «Продолжить», «Играть», «Смотреть». Дополнительные разделы: помощь, достижения, настройки. Кабинет учителя: ученики, назначения, отчёты, профили поддержки, редактор уроков, материалы. Возврат в урок не сбрасывает попытку.

## 3. Visual Learning Path

Постоянные этапы: цель → объяснение → пример → практика → проверка и завершение. У каждого этапа есть устойчивый stageId, заголовок, короткая инструкция, допустимые действия и условие завершения. Показывать текущий этап, число оставшихся этапов и следующий шаг; для завершения показывать «Урок завершён» и дальнейшее действие.

Состояния урока: not_started, in_progress, paused, awaiting_sync, completed. Ошибка сети — отдельное состояние сохранения, а не неправильный ответ. Перед переходом сохранить текущий выбор и этап в локальное хранилище; синхронизировать с локальным backend. Перезагрузка восстанавливает lessonId, lessonVersion, attemptId, stageId, ответы и настройки. Не сохранять повторно выполненный этап как новую попытку.

Кнопки «Назад», «Повтори», «Помощь» доступны во время объяснения и практики. Возврат не стирает уже подтверждённые ответы. Если урок изменился, текущая попытка продолжает закреплённую версию; новая версия применяется к новой попытке. Завершение не зависит от просмотра декоративной анимации или обязательного звука.

## 4. Fraction World

Учебная цель MVP: распознавать долю целого как выбранные равные части. Пример: разделить целое на четыре равные части и выбрать одну. Проверять число равных частей и число выбранных частей; оценка не зависит от способа управления или режима отображения.

Общий task state: taskId, denominator, selectedPartIds, expectedNumerator, hintLevel, submittedAnswer. Режимы используют один state и один evaluator:

| Режим | Представление | Обязательное управление |
|---|---|---|
| 3D | Один объект на спокойной сцене, фиксированная камера по умолчанию | мышь/касание; клавиатурный список долей вне canvas |
| 2D | Вид сверху, одинаковые сектора с отчётливой границей | выбор сектора или эквивалентной кнопки |
| Простой | Плоские карточки и крупные кнопки выбора | Tab, Enter/Space, касание |

Drag-and-drop — только дополнительный способ. Всегда доступна операция «выбрать часть → подтвердить». Фокус и выбранная доля видны; выделение обозначается обводкой и подписью, а не только цветом. При отключённом WebGL автоматически предложить 2D с понятным сообщением без потери прогресса. Не загружать тяжёлый 3D-мир для одной задачи. После ухода со сцены освобождать ресурсы.

Пять демо-заданий: 1/2, 1/4, 2/4, 3/4, 1/3. Сначала короткое обучение управлению без оценки. Подсказки: повтор инструкции → визуальное выделение равных частей → разобранный аналогичный пример. После неверного ответа: нейтральное объяснение и повтор; правильное решение после подсказки учитывается отдельно от самостоятельного. Таймер по умолчанию отсутствует; его скрытие не влияет на результат. Биология и информатика расширяют эту систему после готовности Fraction World, без обязательного создания ещё двух больших миров в MVP.

## 5. Маскот

Один оригинальный персонаж во всех экранах и медиа. Состояния: Idle, Greeting, Explaining, Thinking, Encouraging, Celebrating, Helping. Для каждого подготовить ограниченную анимацию и статичный кадр. При reduced motion использовать статичный кадр; при скрытом маскоте текстовая помощь остаётся доступной. Никаких прыжков поверх задания, обязательного зрительного контакта, фоновой речи или повторяющейся похвалы.

Параметры: visible, voiceEnabled, motionIntensity, textOnly. Маскот не принимает решение о правильности самостоятельно: он озвучивает результат evaluator. Запуск реплики только по явному действию, кроме короткого текстового приветствия. Прерывание аудио немедленное при mute, паузе или «Слишком громко». 3D-ассет и статичная версия должны сохранять один силуэт и палитру.

## 6. Sensory Control и коммуникация

Настройки доступны одним действием из урока, игры и видео. Группы: звук/музыка, движение, визуальная насыщенность, текст, субтитры, темп, видимость таймера, сложность навигации, маскот. Autoplay выключен. На первом входе предложить стандартный и спокойный режим с предварительным описанием; диагноз не запрашивается и не определяет выбор.

Системное prefers-reduced-motion ограничивает декоративное движение независимо от выбранного стандартного режима. Спокойный режим не снижает контраст текста. Настройки применяются сразу, сохраняются между сессиями и имеют кнопку возврата к выбранному базовому пресету. При сбое синхронизации локальный выбор продолжает действовать.

Communication Board содержит: «Я не понял», «Повтори», «Покажи пример», «Мне нужна помощь», «Мне нужен перерыв», «Слишком громко», «Я готов продолжить». Текст и понятная пиктограмма; голос и ввод текста не нужны. «Перерыв» сохраняет урок и ставит медиа на паузу. «Слишком громко» сразу выключает текущий звук, затем предлагает настройки. «Продолжить» возвращает к сохранённому этапу без автоматического звука. Учительская доставка имеет статус «в очереди/доставлено», но не обещает немедленный ответ. Панель не заменяет персональное AAC-средство ребёнка.

## 7. Форматы объяснения и видео

Для одного lessonId и lessonVersion предусмотрены текст, иллюстрация, аудио, видео и интерактивная модель, где она полезна. Переключение меняет представление, сохраняя цель, этап и ответ. Недоступный формат имеет честное пояснение и альтернативу, а не пустую карточку. Не присваивать ребёнку постоянный «тип обучаемости».

Локальный демонстрационный видеоурок о четвертях: 75–90 секунд, одна цель, единый маскот, четыре равные части, субтитры ru/kk и полный текст. Раскадровка в MEDIA_PIPELINE.md рассчитана на 75 секунд, плеер в макете показывает пример длительностью 80 секунд. Начало только по кнопке. Контролы: play/pause, громкость/mute, скорость 0.75/1/1.25, субтитры, повтор фрагмента, возврат к иллюстрации, позиция просмотра. Просмотр видео сам по себе не доказывает освоение темы; после него отдельный мини-тест.

Контракт медиа-адаптера: вход — locale, approvedScriptId, scriptVersion, assetIds; выход — jobId, status, localArtifactPath, subtitlePath, providerMode. В mock-режиме ответы детерминированы, таймаут и ошибка воспроизводимы. Локальная немая анимация с субтитрами допустима как явно подписанный mock без обещания готовой озвучки. ElevenLabs не вызывается даже при наличии ключа. VideoCraft — только если доступен и может работать в разрешённых локальных границах; отсутствие инструмента отмечается как gap, не подменяется заявлением о его использовании. Сценарий и материал проходят учительскую проверку; публикации нет.

## 8. Шесть уроков, каждый на kk и ru

Это шесть уникальных уроков с двумя локализациями каждого, а не три темы, дважды посчитанные по языкам. Следующая сетка — проектное предложение; класс, официальная цель, код и соответствие программе Казахстана требуют проверки педагогом по актуальной программе. Не писать выдуманные официальные коды.

| lessonId | Предмет / предложенный класс | Тема ru / kk | Проектная цель | Критерий успеха |
|---|---|---|---|---|
| math-fractions-01 | Математика / 3 | Равные доли / Тең үлестер | выделять 1/2, 1/3, 1/4 целого | 4 из 5 новых примеров верны; подсказки отдельно |
| math-fractions-02 | Математика / 4 | Сравнение долей / Үлестерді салыстыру | сравнивать доли одинакового целого с одинаковым знаменателем | 4 из 5 сравнений с объяснением через модель |
| bio-plants-01 | Биология / 7 | Органы растения / Өсімдік мүшелері | соотносить корень, стебель, лист с базовой функцией | 4 из 5 соответствий верны |
| bio-cell-02 | Биология / 7 | Клетка и её части / Жасуша және оның бөліктері | узнавать базовые части растительной клетки на схеме | 4 из 5 меток верны |

Каждый урок хранит gradeProposal, topic, objectiveDraft, curriculumVerification="pending_teacher_review", curriculumSource=null до проверки, localeContent.ru, localeContent.kk, materials, tasks, successCriteria, version, reviewStatus, reviewerId и reviewedAt. Переводы выше — черновые и требуют языковой проверки. Один Lesson ID объединяет обе локализации; смена языка не создаёт новую попытку. Учитель подтверждает содержание и язык отдельно. До проверки видна метка «Демо • цель программы требует проверки».

Минимум для каждого: цель, короткое объяснение, иллюстрация, разобранный пример, пять заданий, обратная связь, текстовая альтернатива. Полный 3D/видео MVP обязателен для первого урока; другие уроки используют доступные эквивалентные представления и явно показывают статус ещё не созданных медиа.

## 9. Кабинет учителя и профиль поддержки

Учитель назначает опубликованную локальную версию урока своему ученику или группе, видит статус и последнюю синхронизацию. Отчёт показывает: правильные ответы, неправильные попытки, итог по уникальным заданиям, помощь, подсказки, перерывы, технические ошибки, последний этап и режим конкретной сессии. Фильтры: ученик, урок, период. Знаменатель результата — оценённые задания; не начатые и технически не оценённые задания перечислять отдельно.

Рекомендации — объяснимые педагогические правила с указанием события-основания, например «после визуальной подсказки выполнены два задания; предложить один новый пример». Они редактируются учителем и не становятся диагнозами. Нет рейтинга детей по скорости и «комплаенсу». Профиль поддержки: настройки, заметки учителя, наблюдаемые сильные стороны, темы повторения, полезные подсказки, история версий. Отдельный статус «демонстрационные данные» на всех синтетических отчётах.

## 10. Порядок и результат работы Claude

4. Один локальный видеоурок; отчёты и профили; шесть двуязычных карточек уроков с контентом.
5. Выполнить ACCEPTANCE_TESTS.md и сравнение с визуальными эталонами пакета.
6. Обновить docs/IMPLEMENTATION_PROGRESS.md: выполненное, изменённые файлы, команды и результаты проверок, localhost URL, mock-зоны, оставшиеся gaps. Не объявлять backend или интеграцию готовыми только потому, что нарисован интерфейс.

Остановка этапа: интегрированный локальный сценарий проверен, ограничения перечислены, внешние сервисы не вызваны, деплой и push не выполнялись.
