# Данные, надёжность и доступ

Проектные требования для локального прототипа. Этот документ не является юридическим заключением и не утверждает соответствие конкретному закону. На этом этапе используются только синтетические данные и локальный backend; правила прав доступа всё равно реализуются на сервере.

## 1. Сущности и владение

| Сущность | Обязательные поля и ограничения |
|---|---|
| User | id, role, organizationId, active; роль не принимается из тела запроса |
| StudentProfile | id, userId, organizationId; без обязательного диагноза |
| TeacherAssignment | teacherId, studentId/groupId, organizationId, validity; серверный источник доступа |
| GuardianLink | parentId, studentId, verifiedAt, active; самоназначение запрещено |
| LessonVersion | lessonId, version, locales, reviewStatus; закреплённая версия неизменяема для текущей попытки |
| LessonAssignment | id, studentId, lessonId, version, assignedBy |
| Attempt | id, studentId, assignmentId, lessonId, lessonVersion, stageId, status, revision |
| AnswerSubmission | id, attemptId, taskId, clientSubmissionId, canonicalAnswer, evaluation, evaluatorVersion |
| LearningEvent | eventId, attemptId, type, sequence, payload, occurredAt, receivedAt |
| SupportProfile | studentId, settingsVersion, preferences, teacherNotes; заметки отделены от общедоступного контента |
| MediaArtifact | id, lessonId, locale, scriptVersion, reviewStatus, providerMode, localPath |

Время клиента — вспомогательное, серверное receivedAt хранится отдельно. Пользовательский идентификатор выводится из проверенной сессии. Все внешние идентификаторы валидируются; принадлежность сущности проверяется повторно на сервере.

## 2. Матрица доступа

| Действие | Student | Parent | Teacher | Admin |
|---|---|---|---|---|
| Учиться и отправлять ответы | только своя попытка и назначенный материал | нет отправки от имени ребёнка | только отдельный demo/preview, без подмены ученика | только отдельный demo/preview |
| Читать прогресс | свой | только связанный ребёнок | только назначенные ученики | в своей организации по разрешённой служебной задаче |
| Менять sensory-настройки | свои | связанный ребёнок, изменение видно | назначенный ребёнок, согласованная поддержка | служебное управление, с аудитом |
| Назначать урок | нет | нет | своим ученикам/группе | в своей организации |
| Учительские заметки | только явно помеченная ученическая часть | только явно разрешённая родительская часть | свои назначенные ученики | ограниченный служебный доступ с аудитом |
| Редактировать/проверять урок | нет | нет | по праву автора/рецензента | по праву управления контентом |
| Управлять связями и ролями | нет | нет | нет самоназначения | только своя организация; аудит |
| Экспорт/удаление | запрос своих данных через разрешённый процесс | запрос связанных данных | только разрешённый scoped export | проверенная операция в своей организации |

Роль Admin не означает бесконтрольного чтения всех организаций. Любой запрос проверяет role + organization + объектную связь + допустимое действие. UI-скрытие кнопки не является контролем доступа. Списки, поиск, CSV/экспорт, bulk API, вложения и WebSocket-события используют те же ограничения. Неавторизованному — 401; чужой объект — последовательный 403 или 404 без утечки содержимого. Поле ownerId/role из клиента не расширяет права.

## 3. Корректное оценивание и идемпотентность

1. Клиент формирует clientSubmissionId один раз при намеренном подтверждении ответа. Повтор сетевой отправки использует тот же ID и тот же payload.
2. Сервер проверяет сессию, доступ к попытке, версию задания и состояние попытки. Клиентский isCorrect игнорируется.
3. В одной транзакции выполнить: найти существующую отправку → при отсутствии нормализовать ответ и оценить доверенным evaluator → сохранить результат → записать ровно одно событие → обновить проекцию прогресса.
4. Уникальное ограничение: (attemptId, clientSubmissionId). Повтор того же ключа и payload возвращает ранее сохранённый результат. Тот же ключ с другим payload отклоняется как конфликт, без второго ответа.
5. Уникальный final outcome на taskId в попытке строится по явной политике, например последний принятый ответ после разрешённой повторной попытки. История ошибочных попыток сохраняется отдельно; это не увеличивает знаменатель теста.
6. Завершение — серверная проверка обязательных оценённых заданий. Повтор finish идемпотентен. Двойной клик, два таба и повтор после таймаута не создают двойной балл или повторное завершение.

Состояния отправки UI: draft → pending → accepted; отдельно retryable_error и rejected_validation. При таймауте показать «Ответ сохранён на устройстве, ожидает подтверждения», если он действительно сохранён; не показывать «Неверно». Локальная предварительная проверка может быть помечена «предварительно», но сервер подтверждает итог. Техническая ошибка никогда не записывается как answer_incorrect.

## 4. Event model

Оболочка события: eventId (UUID), schemaVersion, studentId (серверный), attemptId, lessonId, lessonVersion, taskId|null, type, payload, occurredAt, receivedAt, clientSequence, source (student/teacher/system), environment="local_demo". Не писать свободные чувствительные тексты в телеметрию.

| type | Минимальный payload | Правило отчёта |
|---|---|---|
| lesson_started | stageId | начало, не завершение |
| stage_changed | fromStage, toStage | последний принятый этап |
| explanation_mode_changed | fromMode, toMode | режим конкретной сессии, не тип ребёнка |
| answer_submitted | submissionId, taskId | факт приёма, не результат |
| answer_evaluated | submissionId, correct, hintLevel, evaluatorVersion | уникальная подтверждённая оценка |
| hint_requested | hintId, level | поддержка, не ошибка |
| communication_requested | phraseId, deliveryStatus | помощь, не отрицательный балл |
| break_started / break_ended | stageId | перерыв, не неверный ответ |
| technical_error | safeCode, operation, recoverable | техническая проблема отдельно |
| lesson_paused | reasonCode | незавершённость отдельно |
| lesson_completed | completedTaskCount, projectionVersion | ровно одно логическое завершение |
| preferences_changed | changedKeys, settingsVersion | без диагноза и оценки личности |

События client-originated не дают права менять результат оценки. Сервер создаёт answer_evaluated и lesson_completed. Проекции отчёта пересчитываемы по событиям и авторитетным ответам; повтор события с eventId не увеличивает счётчик. Проверять порядок по версиям/последовательности, а не только часам клиента. Изменение настроек и формата не сбрасывает ответ.

## 5. Offline и восстановление

- Локально сохранять минимальное состояние в IndexedDB или существующем надёжном хранилище. Outbox содержит operationId, attemptId, payload, retryCount и состояние; нет секретов.
- Повторная отправка с экспоненциальной задержкой и пределом; ручная кнопка «Повторить». Не создавать бесконечный поток запросов.
- Очередь привязана к userId. При смене аккаунта предыдущая очередь не отправляется от нового пользователя. Logout очищает доступное локальное состояние ребёнка; незавершённая очередь обрабатывается до выхода либо явно отбрасывается после подтверждённого локального сценария.
- Серверные ответы и завершение авторитетны. Для stage/settings использовать revision; устаревшая запись получает конфликт с текущей версией. Не откатывать завершённую попытку старым offline-этапом.
- Для синхронизации настроек конфликт разрешается по проверенной версии: показать выбор актуальной версии или применить документированное merge по отдельным полям. Не использовать недостоверное клиентское время как единственное основание.
- Пока запрос помощи offline, честно показывать «не отправлено учителю». Не обещать получение помощи в реальном времени. Перерыв и mute работают без сети.
- Проверить reload, crash после записи до ответа, повтор reconnect, два таба и смену версии урока. Результат не дублируется.

## 6. Защита локального прототипа

Сохранить существующий механизм auth; не внедрять фиктивную «безопасность» только в localStorage. Если backend ещё отсутствует, явно считать серверные проверки незавершёнными и реализовать минимальный локальный backend до заявления о готовности доступа. Demo switcher допустим только в отдельном режиме с синтетической БД и заметным баннером; не должен обходить обычную авторизацию в другом режиме.

Для cookie-сессий использовать HttpOnly, SameSite и CSRF-защиту согласно существующему стеку; Secure для HTTPS, с документированным localhost-исключением при необходимости. Для токенов следовать существующей проверенной схеме, не хранить ключи сервисов в браузере. Проверять входные данные, размер запросов, загрузки и пути файлов. Вывод заметок и сценариев экранировать; не вставлять произвольный HTML. Ограничить частоту входа и отправки без наказания за использование accessibility-кнопок.

Не выгружать данные детей во внешние AI, аналитику, логи ошибок, ElevenLabs или VideoCraft. В локальном демо не нужны реальные имена, голос, фото, диагнозы или контакты. Медиаматериалы не должны содержать голосовой клон реального ребёнка. Логи — safe codes и технические ID; пароли, сессии и содержимое заметок исключить. Demo credentials не переиспользовать для реальных сервисов.

## 7. Жизненный цикл данных

Метки demo проставляются в seed, UI, экспорте и отчётах. Тестовые данные можно сбрасывать только в точно идентифицированной локальной demo-БД. Перед любой миграцией/сбросом проверить адрес подключения и окружение; production-действия не входят в разрешение.

Предусмотреть scoped export и удаление пользователя/связанных данных с обработкой локального кэша, outbox, заметок и файлов. До реального пилота определить срок хранения и права законных представителей с ответственным за данные; не выдавать выбранные настройки за юридическую сертификацию. Учительские отчёты фиксируют наблюдаемое обучение, не медицинские или психологические заключения.


## Данные дополнения V2.1

TaskVersion хранит objectiveId, subskill, ru/kk content, geometrySpec, answerSchema, rubricVersion, reviewStatus и автора. PreviewAttempt имеет отдельный тип и исключён из оценок ученика. Новое упражнение на перенос понятия ссылается на исходную задачу через transferOfTaskId. События answer_mode_changed, hint_applied и transfer_task_evaluated сохраняют контекст поддержки.

FollowUpAssignment хранит sourceReportId, sourceAttemptId, evidenceEventIds и подтверждение назначившего учителя. Повтор назначения с operationId идемпотентен. Преподаватель редактирует только разрешённый ему контент и назначает только связанным ученикам.

PilotOrder хранит organizationId, createdByAdultId, planId, mode=local_mock, status, idempotencyKey. OrganizationEntitlement хранит разрешённые функции и срок тестового доступа. Сервер сверяет организацию, роль взрослого и право управления подпиской при каждой операции. Дети и чужие организации не меняют entitlement. Провайдер отключён, реквизиты карт не собираются. Авторитетные права не берутся из localStorage. Окончание тестового доступа сохраняет учебные данные. Условия реального тарифа и списания не имитируются как реальные договорённости.
