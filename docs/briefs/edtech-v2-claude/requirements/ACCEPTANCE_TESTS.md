# Приёмка EdTech V2 на localhost

Это план проверок для Claude Code после реализации, а не свидетельство уже пройденных тестов. Использовать отдельную локальную demo-БД. Для каждого кейса записать PASS/FAIL/BLOCKED, фактический результат и подтверждение. Не тестировать на реальных данных детей или production. Все имена и результаты в fixtures синтетические.

## Подготовка

Создать student-A, student-B, parent-A (связан только с A), teacher-A (назначен A), teacher-B (назначен B), admin-A (организация A), admin-B (другая организация). Уроки имеют закреплённые версии; первый урок содержит пять задач Fraction World. Определить реальные команды проекта для targeted tests, typecheck, lint и локальной сборки. В browser network видеть только localhost/локальные ассеты; внешние платные запросы заблокировать тестовым окружением.

## Проверки серверного доступа

Выполнять через HTTP/API напрямую, а не только через скрытые кнопки. Проверить GET/POST/PATCH/DELETE, list/search/export, bulk endpoint и события, если они существуют.

| ID | Действие | Ожидаемый результат |
|---|---|---|
| AUTH-01 | Без сессии запросить профиль/отчёт | 401; данные не возвращаются |
| AUTH-02 | Student-A подставляет ID B в URL и теле запроса | 403/404; нет данных B и изменений его попытки |
| AUTH-03 | Parent-A читает A, затем B | разрешена только разрешённая родительская часть A; B недоступен |
| AUTH-04 | Teacher-A читает/назначает/экспортирует B | отказ; связь с A не даёт доступа ко всему классу/организации |
| AUTH-05 | Admin-B запрашивает организацию A | отказ; admin ограничен организацией |
| AUTH-06 | Ученик передаёт role=admin, ownerId=B, correct=true | права не расширены; оценка вычислена сервером; чужая запись не изменена |
| AUTH-07 | Ввести HTML/script в учительскую заметку и сценарий | отображается безопасный текст; скрипт не выполняется |
| AUTH-08 | После logout использовать старую сессию и другой аккаунт | сессия недействительна; кэш/очередь A не видны и не отправляются как B |
| AUTH-09 | Проверить файлы, bundle и логи | нет ключей, паролей, токенов и чувствительных заметок |

## Форма итогового доказательства

Для каждого блока: ID проверки, окружение, выполненные шаги, фактический результат, PASS/FAIL/BLOCKED, ссылка на локальный скриншот/лог без секретов. Указать localhost URL и роли тестовых аккаунтов, но не публиковать реальные credentials. Отдельно перечислить реализованное, mock, неподтверждённое и не завершённое. Наличие этого плана внутри ZIP не означает, что описанные функции уже реализованы или проверены.
