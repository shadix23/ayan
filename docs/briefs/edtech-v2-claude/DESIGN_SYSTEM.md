# EdTech V2 · дизайн-система и визуальный контракт

Версия 1.0 · 13 ноября 2026. Это спецификация будущего интерфейса. PNG — визуальные макеты, не доказательство работающих функций. Все новые экраны сохраняют язык этой системы; существующее название продукта не заменять рабочим EdTech. Тумо — рабочее имя оригинального маскота.

## 1. Визуальное направление

Мягкий учебный интерфейс: почти белый зелёный фон, белые поверхности, приглушённые мятные и песочные области, тёмный текст, бирюзовый основной акцент. От AlagaLMS берём крупное приветствие, карточки предметов, простую боковую навигацию; от остальных референсов — спокойную персонализацию, крупный объект задания, панель фраз и понятную отчётность. Не смешивать чужие палитры на разных экранах. Не использовать неон, радугу акцентов, фоновые частицы, конфетти или бесконечное покачивание.

Привлекательность достигается формой и ясной композицией. Спокойный режим уменьшает количество декоративных деталей, но не убирает информацию и доступ к помощи. Стандартный режим может добавлять небольшую иллюстрацию, но сохраняет ту же сетку и контраст. Оба режима пригодны для всех детей.

## 2. Токены — обязательные значения

Машиночитаемая версия: `design-tokens.json`. Не добавлять независимые случайные значения цветов и радиусов в каждом компоненте.

| Токен | Значение | Назначение |
|---|---|---|
| background | #F7FAF8 | фон приложения |
| surface | #FFFFFF | карточки, навигация |
| text | #243342 | основной текст |
| textMuted | #526475 | вторичный текст |
| primary | #0F766E | главная кнопка, активная вкладка |
| primarySoft | #E7F2ED | фон выбранного блока |
| mintSoft | #E7F2ED | поддержка, спокойный режим |
| sandSoft | #FFF3D6 | карточка видео |
| border | #DFE7E2 | декоративное разделение |
| controlBorder | #879A96 | контур активного элемента |
| success | #256956 | верно / выбранная часть |
| error | #A33442 | исправимая ошибка ответа |
| focus | #0369A1 | видимый фокус |

Пастельные фоны не использовать как цвет мелкого текста. Border годится для декоративного разделения; для распознавания кнопок/полей использовать controlBorder либо иной контур с проверенным контрастом 3:1. Цвет не является единственным признаком состояния: добавить текст, значок и границу. Контраст текста проверять в готовом приложении, в том числе на hover/disabled/error.

## 3. Сетка и размеры

Основной desktop-эталон: PNG 1440×1024, масштаб 100%. Сайдбар 248px, без floating островов. Контент начинается с x=288 (отступ от сайдбара 40px), заканчивается x=1400 (правый отступ 40px). Верхний заголовок baseline y=70, подзаголовок y=107. Первые карточки y=150. Шкала урока: 5 блоков по 196×70, gap 20, x=288/504/720/936/1152, y=150. Основные промежутки 24/28px. Модуль отступов: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64.

Карточка: радиус 24px, padding 24px, border 1px; обычно без тени. Кнопка: высота 56px, радиус 16px, горизонтальный padding ≥22px. Вкладка/чип: высота 40px для desktop; на touch расширить интерактивную область до 48px, сохранив внешний вид. Иконка 24px, stroke 2px; один набор иконок существующего проекта. Иконки всегда сопровождаются понятным текстом, кроме дублирующих декоративных.

Панель поддержки в макетах: x=272, y=930, w=1140, h=72. В приложении это sticky-блок с зарезервированным местом: не перекрывать контент, фокус или экранную клавиатуру. На маленькой высоте разрешить обычный поток. Скролл страницы допустим, горизонтальный скролл основного контента — нет.

## 4. Типографика

Использовать один локальный шрифт существующего проекта с кириллицей и казахскими Ә Ғ Қ Ң Ө Ұ Ү Һ І (включая строчные). В SVG-макетах Arial/sans-serif — воспроизводимый системный эталон. Не загружать Google Fonts снаружи. При выборе другого шрифта сохранить размеры/высоты строк и ширины блоков, проверить казахский текст и длинные подписи.

| Стиль | Desktop | Mobile | Вес / line-height |
|---|---|---|---|
| H1 | 31–32px | 27px | 700 / 1.25 |
| H2 | 23–24px | 22px | 600 / 1.35 |
| Детская инструкция | 20–22px | 20px | 400 / 1.5 |
| Основной текст | 18px | 18px | 400 / 1.5 |
| Вторичный текст | 16–17px | 16px | 400 / 1.5 |
| Метка учительского отчёта | 15–16px | 16px | 400–600 / 1.4 |

Размеры в rem, пользовательский масштаб не блокировать. Не уменьшать инструкции ради точного попадания в карточку. При 200% допускаются переносы и рост блоков. Капс только для небольших служебных меток, не для длинных инструкций. Выравнивание текста слева.

## 5. Компоненты и состояния

| Компонент | Состояния / поведение |
|---|---|
| Primary button | normal #0F766E; hover #115E59; pressed #134E4A; white text. Loading: спиннер + «Проверяем…», стабильная ширина. Повторная отправка блокируется логикой idempotency, не только disabled. |
| Secondary button | white, controlBorder. Hover primarySoft, pressed #D2E7DE. Текст и граница не теряются. |
| Focus | outline 3px #0369A1, offset 3px; не убирать ради чистоты картинки. Focus-visible на каждом интерактивном элементе. |
| Disabled | нейтральный фон #ECEAF1, текст #646276; объяснить причину. Сохранить читаемость, не прятать кнопку. |
| Toggle | подпись + явное «Вкл/Выкл»; state в accessible name/checked. Область ≥48px. Клавиша Space меняет состояние. |
| Stepper | текущий: бирюзовая граница 2px + номер + aria-current=step; завершённый: значок и текст, будущий: обычный блок. Не переходить вперёд неожиданно. |
| Answer feedback | «Верно: выбрана одна из четырёх равных частей» или «Попробуй ещё: части должны быть равными». Техническая ошибка: «Не удалось сохранить. Ответ остаётся на устройстве»; никакого «Неверно». |
| Dialog/drawer | заголовок, закрыть, возврат фокуса; Escape где безопасно; focus trap только внутри модального окна. |
| Snackbar | короткое подтверждение; role=status/aria-live=polite; не единственный источник важной ошибки. |
| Empty | «Пока нет назначенных уроков» + полезное действие. Не рисовать фиктивную статистику. |
| Loading | понятный текст + статичный skeleton с reduced motion, без мигающей заливки. |
| Offline/error | отделить сохранено локально / ожидает синхронизации / подтверждено сервером. Дать retry без потери выбора. |

Для каждого экрана реализовать happy path, loading, empty, error и offline где применимо; сам макет показывает конкретный основной вид, а не все состояния сразу.

## 6. Предыдущий концепт маскота в макетах

Референс 06-mascot.png фиксирует силуэт: округлая прямоугольная голова, небольшой корпус, одна короткая центральная антенна, две простые руки и ноги, тёмная лицевая панель, две мягкие светлые формы глаз, малый рот, круглый знак на корпусе. Матовое светлое мятное тело и приглушённая медовая деталь. Не копировать робота из внешнего референса деталь в деталь.

3D: локальная модель Blender→GLB, ориентир ≤2MB после оптимизации и ≤30k треугольников; это проектный бюджет, не обещание производительности. Небольшая сцена без postprocessing и вращающейся камеры. Состояния: Idle/Greeting/Explaining/Thinking/Encouraging/Celebrating/Helping; базовая поза должна хорошо читаться и без анимации. Greeting допускает один короткий жест после действия пользователя. Celebrating — краткий спокойный жест, без конфетти и звука. В reduced motion — статичный кадр; при отсутствии WebGL — SVG/PNG с тем же персонажем. Отключение убирает персонажа без пустой дыры, но сохраняет текст подсказки.

## 7. Fraction World: фиксированная учебная сцена

03-fraction-3d.png: одна пицца на спокойной поверхности, камера неподвижна, видны четыре равные части; выбранный сектор получает контур и текстовое подтверждение. 04-fraction-2d.png: тот же выбор и состояние в виде сверху. 05-fraction-simple.png: выбор карточки дроби. Правильность, подсказки, Lesson ID и attempt ID общие. Никакого свободного перемещения по большому миру. Drag имеет альтернативу кнопкой. В 3D обязателен доступный DOM-контроллер выбора всех частей: canvas не единственный способ ответа.

Пицца — один из вариантов контекста. Можно заменить её нейтральным кругом по предпочтению ученика, не меняя доли или математическую цель. Не зависеть от пищевого опыта, цвета начинки или знания слова «пицца». Голос читает дробь словами, формула имеет доступное текстовое представление.

## 8. Видео и аудио

Светлая спокойная сцена, общий маскот, субтитры на тёмной непрозрачной плашке, элементы управления вне текста субтитров. Доступны play/pause, seek, повтор фрагмента, скорость, captions, язык, transcript, переход к модели и мини-тесту. Позиция сохраняется. Не запускать звук на hover или при смене вкладки, даже если внешний референс так делает. В тестовом режиме явно обозначать демонстрационные локальные медиа; не показывать фиктивную платную генерацию как готовый урок.

## 9. Responsive

≥1200px: desktop-сетка макетов. 768–1199px: боковую навигацию заменить компактной, карточки 2 колонки, основной материал и помощник в поток. <768px: одна колонка, поля 20px (на 320px — 16px), порядок заголовок → текущий шаг → инструкция → содержимое → проверка → помощь. 13-child-mobile.png — эталон 390×844. Длинный stepper заменять кратким «Шаг 3 из 5 · Далее: практика» с раскрываемым полным списком. Ничего важного не прятать только в hover. Teacher-таблицы преобразовать в карточки либо обеспечить отдельный управляемый скролл, не сжимать подписи до нечитаемости.

## 10. Motion

По умолчанию музыка/эффекты/autoplay выключены. Декоративное движение выключено при reduced motion; пользователь может выключить его независимо. Переходы 120–180ms только opacity/небольшое изменение цвета; в reduced motion 0ms. Никаких вспышек, параллакса, shake при ошибке, бесконечного bounce и принудительного таймера. Изменение настроек не перезагружает урок.

## 11. Как Claude подтверждает соответствие картинкам

1. До реализации открыть все PNG и UI_REFERENCE_MAP.md. Зафиксировать переиспользуемые компоненты.
2. После реализации снять локальные скриншоты при 1440×1024 и 390×844, 100% масштабе, RU, синтетических данных, загруженных локальных шрифтах, выключенных анимациях. Использовать те же основные состояния, что в макетах.
3. Сравнить рядом и полупрозрачным наложением. Проверить ширину навигации, отступы, заголовки, иерархию, размеры карточек, кнопки, размещение помощи, цвета и выбранные состояния. Крупные опорные границы: отклонение ≤8px при эталонном viewport; font-size ±1px и радиусы/цвета по токенам. Антиалиасинг текста и 3D-рендер допускают различия.
4. Нельзя заменять композицию большим hero-блоком, менять sidebar на topbar на desktop, делать мелкие кнопки, произвольно менять палитру или убирать поясняющие подписи. Доступность, длинный казахский текст и увеличение шрифта важнее координат — такие отклонения описать в отчёте.
5. Отдельно проверить keyboard-only, 200% zoom, 320px reflow, отключённый WebGL, reduced motion, отсутствие звука и запросы к внешним доменам. Красивый PNG не заменяет эти проверки.

Итог: `docs/VISUAL_QA.md` со скриншотами каждого экрана, списком отклонений и проверками доступности. Не объявлять pixel-perfect или WCAG-conformant только по наличию макетов.
