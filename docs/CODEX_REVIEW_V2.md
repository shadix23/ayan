6. **[high] Позднее подтверждение старого ответа скрывает новый правильный ответ.**

**Подозрения и сценарии, требующие отдельного теста**

- **[high] Очередь старой вкладки может примениться к другому ребёнку.**  
  **Где:** `dist/v2/ui.mjs:83–101`, `server.mjs:75–81`, `learning.mjs:219–225`.

  `userId` изолирует только ключ localStorage; запросы используют текущую cookie. Если в другой вкладке войти как ребёнок B, старая вкладка A может отправить настройки A через `/api/support?role=child` уже от имени B. Запрос помощи тоже принимается, даже если его чужой `attemptId` преобразован в `null`.

  **Проверка:** две вкладки, очередь A, смена аккаунта на B, затем flush A. **Минимальное исправление:** серверная проверка ожидаемого пользователя операции против текущей сессии и остановка очереди при смене аккаунта.

- **[medium] Legacy grading принимает V2 attempt.**  
  **Где:** `server.mjs:72`, `progress.mjs:97–102`.

  Legacy `/api/attempt/submit` не отвергает V2 snapshot. Запрос с `taskId:"final"` может добавить фиктивный `incorrect` в общую таблицу submissions. Возможность записи следует из кода; влияние на итоговый пользовательский отчёт нужно воспроизвести.

  **Минимальное исправление:** проверять версию контракта урока до legacy grading и отклонять V2 attempts.

- **[medium] Граница бесплатного followup и платного constructor не закреплена серверным контрактом.**  
  **Где:** `learning.mjs:358`, `learning.mjs:107–112`.

  `followup:true` позволяет сохранить произвольные constructor fields, а `kind:"followup"` обходит constructor entitlement при наличии любого собственного `sourceAttempt`. Однако бесплатный редактируемый followup явно предусмотрен клиентом, поэтому сам обход нельзя уверенно считать нарушением тарифа.

  **Проверка:** определить допустимые ограничения бесплатного followup и проверить их прямыми API-запросами. Если ограничения нужны, **минимальное исправление** — проверять происхождение followup и связь с исходным учеником и попыткой на сервере.

**Что выглядит корректным и чем это подтверждено**

- Дроби оцениваются по площади целочисленным перекрёстным умножением. Тесты покрывают неравные части, нормализацию, недопустимые ответы и способы ответа.
- V2 grading использует закреплённую серверную версию урока; клиентский `correct` не определяет оценку. Завершение требует правильных ответов для всех `required`.
- Детерминированный `done:<attemptId>` предотвращает повторную запись `lesson_completed` для одной попытки. Он не устраняет описанные сбои между SQL-запросами.
- В проверенных `report`, `export`, `student/delete`, `support`, `help/seen`, templates и preview есть проверки владельца. `admin/overview` ограничен организацией и возвращает агрегаты.
- Пользовательские заметки, метки и поля конструктора в просмотренных HTML-вставках проходят через `esc()`. Подтверждённого XSS в этих местах не найдено.
- Demo API закрыт при `AYAN_DEMO !== '1'`; запуск demo запрещён с PostgreSQL, Vercel и `NODE_ENV=production`. Отдельная проблема выбора SQLite-файла описана выше.
- Media adapters не отправляют платные запросы. Ключи сами по себе не включают LLM: требуется `AYAN_PAID_PROVIDERS=enabled`. При этом путь внешних вызовов в `server.mjs:94–97` остаётся, поэтому строгий режим «local only» не является безусловным.
- Обычные диалоги используют `<dialog>`, возвращают фокус; CSS учитывает reduced motion. Calm mode выбирается пользователем, а не выводится из диагноза.
