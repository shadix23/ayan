## Миграция и откат

- При старте сервера: `CREATE TABLE IF NOT EXISTS ayan_lesson_versions, ayan_attempts, ayan_submissions`; `ALTER TABLE ayan_events ADD COLUMN lesson_version, attempt` (ошибка «колонка уже есть» игнорируется); существующие уроки получают `version: 1`, копия пишется в `ayan_lesson_versions`.
- Проверено на локальной базе с прежними данными: 4 урока, после старта 4 версии, 0 уроков без версии, в `ayan_events` появились обе колонки.
- Откат: вернуть прежние `server.mjs` и `dist/*`. Новые таблицы старым кодом не читаются, новые колонки допускают NULL. В JSON урока остаются лишние поля `version`, `answerKeyVersion`, старый код их игнорирует.
- **Не проверено на копии рабочей базы Neon** (доступа к ней у меня нет). ТЗ требует тест миграции на обезличенной копии до выкладки.

## Pending review / известные ограничения

- **A4: результаты игр задаёт клиент.** Ребёнок может отметить все игры пройденными через `PUT /api/state`. Исправление требует серверной проверки игр; запланировано вместе с новыми играми этапа 3.
- Наблюдения разделены по ученикам внутри состояния кабинета учителя (`ayan_teacher_state`), отдельной таблицы нет. Старые наблюдения без ученика при нескольких учениках скрыты (не удалены), при одном ученике привязываются к нему при следующем сохранении.
- Политика отчёта по повторным попыткам: в отчёт попадают все ответы всех попыток, по версиям. Выбор «лучшая / последняя» не делался.
- Пункт 8 SECURITY.md (кнопка «Назад» после выхода) вручную не проверялся; ответы API идут с `no-store`.
- Миграция не проверена на копии рабочей базы.
