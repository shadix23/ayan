# Доступ и данные: требования к реализации
Это список проверки конкретного проекта, не результат выполненного аудита.

## Матрица прав
| Действие | Ученик | Учитель | Родитель/представитель | Оператор |
|---|---|---|---|---|
| Учебный контент | Разрешённый и опубликованный | Свой контекст/назначения | Разрешённое ознакомление | По служебной роли |
| Ответы и прогресс | Свои разрешённые поля | Только назначенные ученики | Только связанные дети и разрешённые поля | Только при необходимости и с журналом |
| Учительские заметки | Нет | Своих учеников по политике школы | Не автоматически; отдельная политика | Ограниченно |
| Назначение/публикация | Нет | По явному разрешению | Нет | По отдельной роли |
| Экспорт/удаление | Запрос по процедуре | В пределах полномочий | Запрос по процедуре | Исполнение подтверждённой процедуры |

Связь родитель–ребёнок нельзя установить просто вводом studentId. При снятии назначения/привязки доступ отзывается; сессия и кеш не должны его продлевать. Разделяй tenant/school при наличии нескольких организаций. Не добавляй роль «админ» каждому учителю.

## Поверхность проверки
API уроков, ответов, прогресса, заметок, отчётов, экспорта, списков учеников; GraphQL/subscriptions если есть; загрузки, обложки с персональными данными и приватные видео. Публичный общедоступный учебный ролик не содержит данных детей. Для приватных материалов доступ проверяется при выдаче, URL ограничены сроком и назначением. Не кешируй личные ответы/отчёты в общем CDN или service worker без изоляции.

При cookie-auth проверь CSRF и атрибуты cookie; при токенах — срок, отзыв и безопасное хранение. Валидируй поля на сервере, защищай вывод заметок от XSS, ограничивай размеры/типы загрузок. Не позволяй входным URL генератора обращаться к внутренним ресурсам. Не записывай ключи, токены, полные детские диалоги и персональные данные в ошибки/аналитику.

## Минимальные отрицательные проверки
1. Аноним открывает прямую ссылку, API и экспорт → отказ без личных данных.
2. Ученик A подменяет ID в GET/PATCH/POST/скачивании для B → отказ; данные B неизменны.
3. Учитель школы/класса A открывает B → отказ; список не раскрывает B.
4. Родитель меняет childId на несвязанного ребёнка → отказ.
5. Клиент подставляет score=100, роль и признак completed → сервер не доверяет этим значениям.
6. После выхода/отзыва роли/связи запросы повторяются → отказ.
7. Повтор идемпотентного запроса возвращает тот же результат только тому же владельцу и в том же контексте.
8. Вышедший пользователь нажимает «Назад» и открывает кеш → чужой отчёт не раскрывается.

## Пакет доверия до пилота
Заполнить фактические: оператор/контакты, данные, цели и основание, срок, место базы/копий/логов, обработчики и трансграничные потоки, процедура доступа/исправления/удаления, сроки исполнения, судьба резервных копий. Согласие представителя и понятное объяснение ребёнку, отзыв и отказ без принуждения. Удаление включает БД, файлы, поисковые индексы/аналитику по применимости; резервные копии имеют срок очистки и защиту от повторного восстановления удалённых записей. Политику проверяет ответственное лицо с учётом актуального закона РК. Шаблон с незаполненными полями нельзя выдавать за действующее согласие.
