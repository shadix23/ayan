# Прогресс, наблюдения и поддержка

## Состояния ответа
`editing → submitting → saved → evaluated`. При сети: `submitting → save_failed → retry`. `incorrect` — результат проверки сохранённого ответа, не ошибка сети. Не показывай «Урок завершён», пока сервер не подтвердил завершение. При неопределённом исходе сначала запроси сохранённый результат по attemptId, затем повторяй безопасно.

Двойной клик, повтор после timeout и две вкладки не создают дубликаты. Примерный уникальный ключ: ученик + attemptId + taskId + submissionId. Сервер контролирует владение ключом и версию; конфликт содержимого под тем же ключом отклоняется. Завершение попытки и агрегат отчёта согласованы транзакцией либо воспроизводимым обработчиком с дедупликацией. У офлайн-очереди есть явный статус; локальные данные не смешиваются между учениками.

## Наблюдения
Каждая заметка содержит studentId, lessonVersion, authorId, время, контекст и видимость. Не записывать заметку на уровне общей карточки урока, если она о конкретном ребёнке. Отчёт отделяет ответ без подсказки, с подсказкой, пропуск и неподтверждённое сохранение. Пустое значение не превращается в нулевую успеваемость.

## Профиль поддержки
Предпочтительный язык, темп инструкций, субтитры, размер текста, движение/звук, способ ввода, повтор объяснения. Настройки доступны взрослому в пределах прав и ребёнку в безопасной части. Никаких диагнозов, выводов об интеллекте и скрытой классификации «слабый». Предпочтения не снижают доступ к содержанию и не меняют учебную цель молча.

## Пример текстов
- «Ответ пока не сохранён. Попробуем ещё раз» — сохранение не удалось.
- «Сохранено. Можешь продолжать» — сервер подтвердил.
- «Ты выбрал 2 части из 4. Для одной четверти нужна 1 часть» — объяснение задания.
- «3D пока не загрузилось. Решим эту же задачу на картинке» — доступная альтернатива.
- «Видео готовится. Можно прочитать объяснение» — отсутствие ролика.
